# Security Leadership — Executive Portfolio

A restrained, editorial portfolio for an experienced cybersecurity executive focused on information security leadership, cloud security and AI governance. Includes an evidence explorer for [Agent Governance Kit](https://github.com/haxforscience-eng/agent-governance-kit).

**Preview edition:** the owner has not yet supplied a public name, biography, certifications, professional achievements or contact address. None are invented. The site's profile and provenance section clearly states that limitation and discloses OpenAI Codex assistance. The GitHub handle is the account authorized by the owner.

## Review locally

Requires Python 3.11+ for a local server and Node.js 20+ for artifact checks. No JavaScript packages or build installation are required.

```sh
node scripts/check-site.mjs
python -m http.server 8080 --bind 127.0.0.1 --directory dist
```

Open `http://127.0.0.1:8080/`. The workbench fetches same-origin static JSON, so use HTTP rather than double-clicking a local HTML file.

## Structure

- `dist/index.html`: executive portfolio and leadership perspective.
- `dist/workbench.html`: selectable synthetic governance receipts, evidence and limits.
- `dist/assets/`: CSS, small vanilla JavaScript module and SVG mark.
- `dist/data/evidence.json`: generated by the real Python fixture demo.
- `dist/downloads/`: executive brief, operating model and complete open-source source archive.
- `docs/`: review/deployment checklist and development record.
- `.github/workflows/pages.yml`: GitHub Pages publishing workflow with pinned action commits.
- `.openai/hosting.json`: private Sites preview identity. GitHub Pages does not need this file; it deploys only `dist/`.

All paths are relative, supporting both a repository-based GitHub Pages URL and the private Sites preview. No analytics, remote fonts, cookies, local storage, trackers, form submission or external APIs are used. The browser workbench displays exported evidence, not live authorization. It never runs agents or grants approvals.

## Publish to GitHub Pages

1. Create or use the `security-leadership-portfolio` repository under the owner's authorized account.
2. Push the reviewed files to `main`.
3. In Settings → Pages, select **GitHub Actions** as the source.
4. Run **Publish portfolio to GitHub Pages** if a push has not already triggered it.
5. Check the actual successful deployment URL. Do not assume that a committed workflow means the site is published.

Review `docs/REVIEW-AND-DEPLOY.md` before using the portfolio professionally. Add only verified career details, contact destinations and supporting evidence. Preserve the authorship disclosure.
